# NEXT PLAN — Gate D 以降

数値しきい値に「（案）」と付いているものは、**実行前に事前登録して固定する提案値**です。この監査の中では一度も計測していません。
`fx` は現行カメラの焦点距離（px）です。例として使う fx≈1500 px は、旧 ELP の 1280×720 値を 2592 幅へ単純に換算した**仮定**であり、現行値ではありません。

---

## A. 証明済みとして維持するもの

カメラ固定制御（focus 400 / AF OFF / exposure 300 / gain 16 / AWB OFF / 4600K）、2592×1944 撮影契約、reopen 再現性（N1/N2 15/15、40/40）、production intrinsic campaign framework、独立 holdout という考え方、fixed-K/D 検証の手順、revB の STRUCTURED_RESIDUAL_RECURS 判定（＝現行 K/D は昇格不可）、9×7 への復元方針、69.3 cm の撮影証拠、検出器フラグ問題の発見、OS0-128 dynamic baseline、P1 ON 検証、qualified dynamic bag。

旧資料に、これらを覆す内容はありませんでした。

## B. 旧資料から取り入れて改善するもの

1. **ボードの型は旧資料と同じ 9×7（A3、ファイル名上は 40 mm）**（E12）。復元方針は旧資料とも整合します。ただし旧資料でも紙を段ボールに貼っただけで、寸法も平面度も一度も測っていません（E11, E14）。→ **D1 でボードを計測**します。
2. **旧資料は zoom / pan / tilt / crop を一切記録していません**。旧 K の cy は中心から −45 px ずれています（E10）。→ 現行も、制御一致チェックの対象に zoom / pan / tilt が入っているかを確認します（**D0**）。
3. **旧資料の「成功」は学習誤差 ≤0.5 だけで判定されています**（E05, E06）。現行の holdout 基準のほうが厳しいため、「旧は通っていた」は根拠になりません。逆に、**現行の合否基準を用途の誤差予算に結びつける**ことで、過剰な厳密化を避けられます（F-7）。
4. **時刻**：旧資料は、時刻ドメインが違えば着色が空振りすることと、最新画像フォールバックが誤差を隠すことを実体験として残しています（E31–E34）。→ 時刻は設定ではなくデータで測ります（I）。
5. **フレーム**：旧資料では os_sensor と os_lidar の 180° の違いが、少なくとも2回混入した疑いがあります（E22, E29）。→ extrinsic には frame_id を必須で記録します（H）。

## C. 再撮影が必要なもの（条件付き）

- **E の判定が「board-locked」または「判別不能」の場合のみ**、9×7 で学習 24 ポーズ＋holdout 12 ポーズ（C-1）を撮ります。
- **判定が「image-locked」の場合**は、モデル比較（E-4）の後に **9×7 で holdout 12 ポーズだけ**を撮ります。新モデルをクリーンなボードで確認するためです。学習用の撮り直しはしません。
- **判定が「detector-locked」または「zoom/pan/tilt 不一致」の場合**は撮影不要です。既存画像を再処理するだけで済みます。

### C-1 撮影仕様（必要な場合のみ）

**なぜ必要か**：既存の campaign と holdout は加工した 9×6 で撮っています。9×7 の画像は、正面中央の 5 枚しかありません。正面中央だけでは歪み係数も焦点距離も拘束できません。

**事前計算**：既存の 69.3 cm の画像から、ボードの内コーナー bbox 幅 / 2592 を測ります。旧 ELP と同じレンズだと仮定すると約 23% になります（280 mm × fx / 693 mm）。

| 区分 | 枚数 | 目的 | 配置 | 傾き |
|---|---|---|---|---|
| T01–T12 | 12 | 歪み・主点：画像全域の網羅 | 4×3 グリッド（ボード中心が x≈12/37/63/88%, y≈15/50/85%）。端の位置ではコーナーが画像境界から 5% 以内に入ること | 画像中心へ向けて 20–30° |
| T13–T20 | 8 | 焦点距離：遠近の手がかり | 中心付近（x, y とも 35–65%） | yaw ±40°、pitch ±40°、対角 4 方向 (±30°, ±30°) |
| T21–T22 | 2 | fx/fy・接線歪みの相関を切る | 中心 | roll ±45°、傾き 15° |
| T23–T24 | 2 | 奥行き方向の変化 | 中心、0.5 m と 0.9 m | ≤15° |
| H01–H12（holdout・**別セッション**） | 12 | 独立検証 | 画像四隅 4（傾き ~20°）、辺中点 4、中心で傾き 35° を 2（学習とは異なる軸）、69.3 cm 正面を 2 | — |

- **距離**：基本は合焦帯（69.3 cm ±10 cm）です。focus は 400 のまま変えません。T23/T24 がぼける場合は「被写界深度の限界」として記録し、そのポーズは除外します。
- **各ポーズで3フレーム連写**します。最も鮮鋭な1枚を採用し、3枚の間のコーナーのばらつきを**ノイズフロア σ_n** として記録します。
- **フレームの受入条件（案）**：
  - 検出器 A（SB：EXHAUSTIVE｜ACCURACY｜NORMALIZE_IMAGE）と検出器 B（classic＋cornerSubPix）の両方で 48/48 コーナーを検出すること。
  - A と B のコーナー位置差の中央値 ≤0.15 px。
  - `cv2.estimateChessboardSharpness` の平均 ≤3.0 px（既存の 69.3 cm 画像で値を確かめてから固定する）。
  - ボード上に飽和画素がないこと。
  - 制御値と zoom/pan/tilt のメタデータが契約と完全に一致すること。
- **網羅性の受入条件（案）**：
  - 画像を 4×4 に分けた各セルに、6 コーナー以上を含むフレームが1枚以上あること。
  - 画像の上下左右4辺の外周 5% 帯に、それぞれコーナーが入っていること。
  - yaw と pitch のそれぞれで |傾き| ≥30° のフレームが4枚以上あること。
- **失敗・停止条件**：
  - 1つのポーズ枠は最大3回まで試します。それでも検出できなければ「検出器の失敗」として記録し、別のポーズで代用しません。
  - 3枠以上が失敗したらセッションを中止して解析に戻ります。
  - 計画外の追加撮影はしません。

## D. 再撮影しなくてよいもの

カメラ制御と再現性（N1/N2）、解像度契約、revB の結論、OS0-128 の Gate B 一式。既存の 9×6 campaign と holdout は、**原因の切り分けには使います**。最終 production の K/D に使うかどうかは、E の判定次第です。

## E. Intrinsic の最小次アクション（撮影もソルバ再実行もしない）

**E-0 メタデータ監査（机上）**
campaign、holdout、revB、restored_9x7 の全画像について、resolution、pixel_format、zoom_absolute、pan_absolute、tilt_absolute（デジタル PTZ はクロップ位置を変えます）、focus、exposure を一覧にします。
→ 1つでも不一致があれば、それが最有力の原因です。データを状態ごとに分けて解析をやり直し、ここで止めます。

**E-1 ボード計測（物理作業約20分、カメラは使わない）**
9×7 ボードについて次を測ります。
- 内コーナー範囲 7S×5S（鋼尺で両軸）と、両対角。
- 直定規とすきまゲージで、3方向の平面度。
- 受入条件（案）：X/Y スケール比のずれ |Sx/Sy−1| ≤0.1%、対角の整合 ≤0.5 mm、平面度 ≤0.3 mm。
- 実測した S を以後の公称値とします。

印刷の縦横スケール差は、K/D では吸収できない**構造残差**を生みます。一方、正方形の寸法誤差そのものはボードの並進量しか変えません。

**E-2 2種類の検出器で再検出（計算のみ）**
既存の全画像を、検出器 A と B で再検出します。コーナーごとの A−B 差と鮮鋭度を記録します。

**E-3 残差の帰属分解（計算のみ、ソルバなし）**
revB の fixed-K/D の残差ベクトルを、次の3通りに集約します。
(i) 画像座標の 4×4 ビン平均、(ii) ボード上のコーナー番号ごとの平均（覆った行に隣接する行は別集計）、(iii) A−B の検出器差。
それぞれが説明する分散の割合を出します。判定ルール（案、事前登録）は次のとおりです。

| 判定 | 条件（案） | 次の行動 |
|---|---|---|
| detector-locked | 検出器を A↔B で入れ替えると構造残差が 50% 以上減る、または A−B 差の大きさが残差と同程度 | 検出器を固定して再評価。撮影不要 |
| board-locked | コーナー番号ごとの平均で説明できる分散 ≥ 画像ビンで説明できる分散。または覆った行の隣で残差が有意に大きい | 9×6 データを production から除外 → C-1 |
| image-locked | 画像ビンで説明できる分散が優勢（放射状・周辺部に集中） | E-4 |
| 判別不能 | いずれも有意でない | C-1 |

**E-4 モデル比較（既存の検出結果のみ、事前登録してから実施）**
campaign を学習、独立 holdout を試験として、{k1,k2,p1,p2} / {+k3} / rational（k1..k6）を比較します。holdout で構造残差の基準を満たす**最も単純なモデル**を採ります。`calibrateCameraExtended` の標準偏差で、パラメータが弱くしか拘束されていないかも確認します。
旧資料が k3=0 の単純なモデルだったことは参考になりますが、解像度も視野も違うので根拠にはしません。

## F. Intrinsic の PASS 条件（案、事前登録）

1. **メタデータ**：全フレームで制御値・zoom/pan/tilt・解像度・フォーマットが一致。
2. **検出**：C-1 のフレーム受入条件を満たす。
3. **ノイズフロア**：連写から σ_n を測定済み。
4. **holdout**（独立セッション、K/D 固定）：全体 RMS ≤ 学習 RMS の 1.5 倍、かつ p99 コーナー誤差 ≤ 3×RMS。
5. **構造なし**：4×4 画像ビン（30 コーナー以上のセル）の平均残差ベクトルと、ボード番号ごとの平均が、統計的に有意でない（|平均| ≤ 3·SE）か、0.25 px 以下。revB の3条件はそのまま併用します。
6. **安定性**：2分割または bootstrap で得た2つの K/D について、網羅領域の格子上での投影差の最大値 ≤0.5 px。
7. **用途の誤差予算**：holdout の p99 誤差を角度に換算し、LiDAR の水平角度ステップの 1/4 以下であること。
   - OS0-128 の 1024 列モードでは 0.352° なので 0.088° 以下（fx≈1500 なら約 2.3 px）、2048 列モードでは 0.044° 以下（約 1.15 px）。
   - **重要**：p95 の yaw 速度 30.6°/s で時刻誤差が 10 ms あると、0.31°（約 8 px）ずれます。exposure 300 が UVC 単位（100 µs）なら露光は 30 ms で、ぶれは約 0.9° です。**色ずれの支配要因は intrinsic ではなく時刻と動き**です。holdout 残差がサブピクセルなら、構造残差は「科学的には実在するが運用上は無視できる」と判定できます。この条件で Gate D を閉じてよいと考えます。

## G. Extrinsic へ進む条件

F の 1〜7 がすべて PASS、K/D を凍結してハッシュを記録済み、Gate A で機械固定（ウィットネスマーク付き）を完了、カメラとマウントを以後動かさない、の4点。

## H. Extrinsic の較正方法（数値は旧資料から持ち込まない）

- **変換の定義**：`T_cam_lidar`、p_cam = R·p_lidar + t、単位はメートル。
  - source は **実際の PointCloud2 の header.frame_id**（os_lidar か os_sensor かを `ros2 topic echo` で確認して記録）。
  - target はカメラ光学フレーム（X右 / Y下 / Z前）。
  - 3×3 行列と四元数（xyzw）で保存し、RPY は使いません。
- **ターゲット**：剛体の大型平面ボード（目安 600×450 mm 以上。9×7 A3 は LiDAR の平面抽出には小さい）を、**三脚に固定**します。ChArUco にすれば部分的に見えても検出できます。
- **データ**：静止ポーズ 12 以上（距離 1.5–4 m、左右・上下・傾きを分散）＋holdout 4 ポーズ。各ポーズで 1 秒以上静止し、静止区間のスキャンを平均します。**静止させることで、外部パラメータの推定を時刻オフセットから切り離せます**（旧資料は手持ちだったため、両方が混ざっていました）。
- **ソルバ**：カメラ側は solvePnP（K/D 固定）でボード平面を求め、LiDAR 側は RANSAC 平面＋境界線を求めます。点と平面の距離（＋辺の制約）で T を最小二乗推定します。独立チェックとして direct_visual_lidar_calibration（ROS 2 Humble 対応、targetless）を走らせ、両者の差を確認します。
- **検証（案）**：holdout ポーズで点–平面 RMS ≤ 1.5 cm、ボード辺の再投影 ≤ 予算 F-7 相当。
- **再現性**：日を分けた2セッションで、並進差 ≤1 cm、回転差 ≤0.1°（案）。

## I. タイムスタンプの検証方法

1. 各ストリームの時刻ドメインを**データで**確認します。LiDAR、IMU、画像の header.stamp の値域と、受信時刻との差の分布を見ます（旧資料では設定と実データが食い違っていました、E34）。
2. 画像のタイムスタンプが V4L2 バッファのどの時点（露光開始・露光中央・露光終了・受信）を指すかを確定します。exposure 300 の実単位も `v4l2-ctl` で確認します。
3. **オフセット推定**：H の後、静止した高コントラストのボードや縦エッジの前でリグを回します。δ を −100〜+100 ms の範囲で走査し、LiDAR の辺の投影が画像の辺に最もよく合う δ_cam を選びます。3回繰り返し、ばらつき ≤3 ms（案）。
4. P1 の +10 ms 残差とは独立に扱います。δ_cam は extrinsic と同時には推定しません。

## J. オフライン着色の設計

1. **入力**：凍結した canonical map（点順序は不変）、LIO-SAM の poses、同期済みの画像、凍結した K/D と T_cam_lidar と δ_cam。
2. **姿勢**：画像時刻 t_img+δ_cam の姿勢を、軌跡から補間（SLERP＋線形）して求めます。最近傍画像による代用はしません。
3. **投影**：世界座標 → カメラ座標 → `projectPoints`（歪み込み、元画像上で投影）。Z>0 と境界マージンを確認します。
4. **遮蔽**：画像ごとに深度バッファ（縮小解像度可）を作り、相対許容（例：深度の 2%＋5 cm、案）を超えて奥にある点を棄却します。
5. **マルチビュー融合**：視線と法線の角度、画像中心からの距離、深度、角速度（動きぶれ）で重み付けします。角速度がしきい値を超えるフレームは除外します。
6. **決定性**：画像は時刻順に固定、集約は double で順序固定、タイブレーク規則を明示します。
7. **未着色の扱い**：灰色で埋めず、`color_valid`（uint8）などの別フィールドで区別します。

## K. PCD 保存の QA

着色前後で次が完全に一致することを確認します：点数、width、height、点順序、XYZ のビット列、NaN/Inf マスク、既存フィールドの名前・型・COUNT・値、DATA 形式（ascii / binary / binary_compressed）。
変化してよいのは、追加した rgb と color_valid のフィールドだけです。rgb の符号化（float 詰め込みか uint32 か）を明記し、CloudCompare と PCL の両方で読めることを確認します（旧資料では変換スクリプトが必要でした、E44）。
同じ入力で2回実行し、出力のハッシュが一致することを確認します。manifest には入力・設定・コードのハッシュを記録します。

## L. 最終的な production ワークフロー

Gate A（機械固定・ウィットネスマーク）→ カメラ契約の確認 → K/D 凍結（Gate D）→ T_cam_lidar 凍結（H）→ δ_cam 凍結（I）→ 計測 bag の記録 → LIO-SAM（無着色）→ 軌跡の妥当性ゲート → オフライン着色（J）→ PCD QA（K）→ manifest とレポート。
各段の凍結値を変更したら、それより後の段はすべてやり直します。
